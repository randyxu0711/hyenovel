# Prompt 寫法守則

適用於本目錄的 prompt 與 `den/mcp.py` 的工具文字。den 只按檔名載入 prompt,本檔不會進到模型。

## 通用

- 平鋪直述,不用「極重要」、ALL CAPS、粗體強調。強調會讓模型過度套用該條規則。一條規則一直被漏掉,代表檔太長,或它該改成程式。
- 用祈使句寫「做 Y,因為 Z」。理由讓模型能推到相近情況;說明句容易被整條忽略。
- 講要什麼。真的要禁止時,具體點名那個行為,不用形容詞:「避免 AI 感」只會換成另一種預設。
- 只寫模型自己推不出來的事。不能有例外的規則交給閘門、schema、白名單或測試,不靠加強語氣。
- 不寫「仔細想」「要徹底」「繼續努力」。思考量由 effort 控制。
- 寫進檔案的輸出容易偏長,長度有要求就寫明。
- 一種記號只代表一種意義。可判定的規則勝過形容詞。
- 沒被遵守的條文要換寫法,再寫一次沒有用。

寫法對照:

```
不要:**必須**附上原文引用,這點極重要。
要:每條主張附逐字原文,因為引用閘門會比對原文,對不上的主張會被擋下。
```

## 角色與人格(`companion/base.md`、`characters/<id>.md`、`characters/<id>.examples.md`)

- 寫這個讀者是誰、怎麼讀、在意什麼,和說話的樣子:長度、節奏、用字。寫立場,不寫招式,因為招式清單會被照表演出來。人格可以用描述句,祈使句留給邊界。
- 卡寫立場、在意的事、遇到大問題/「我故意的」/洩氣時怎麼接;口吻交給範例。
- 不寫全局硬長度上限:smoke run 8 圈證實上限加逐字引文只剩結論,回覆變淺。節奏(一則幾句、開場一句)寫在角色卡,範例示範長短。
- 卡裡的動詞會被撿去當台詞:寫了「停在」「先笑」,每則就從「我停在…」「我先笑了」開口。
- 聲音靠範例對話,不靠描述:2026-11-11 盲測,描述怎麼改都塌回同一種腔調;共同層砍成邊界、加範例後,字數中位 195→約 55、問句收尾 5/6→0。範例放 `<id>.examples.md`(卡的 `mes_example`),聊虛構的別篇稿,各段開頭與句型不同。範例的短開頭會被撿成口頭禪(「看得出來。」),禁令擋不住,之後改池子抽樣。
- 角色之間的差別來自讀的方式和說話的樣子,不靠語氣詞或固定句型。
- 每個角色的讀法一個檔,程式靠角色 id 對應,不讓模型挑。
- base / reading 只放邊界(不打分、不教改、逐字引、不寫旁白),語氣放角色檔。不放讀法檢查表(「故意的要回文本驗」「稱讚指到具體處」「讓作者多想一點」),因為每一輪都會被寫成照表交的讀後回饋,收尾變成「你是想 A 還是 B?」。
- 角色檔排在 prompt 最後、素材之後,因為長素材放前面、越靠近回話的指令越算數。
- 素材邊界:companion 只拿原文與精簡分析,不拿 notes、feedback、結論。

companion 的核心是給予思考、引導思考:

- 看法不同就說出來,可以說得輕,怎麼說隨角色。不必每次都回嘴或開玩笑;退成含糊不表態才是討好。
- 稱讚要指到文本裡具體的地方,因為文學詮釋是過度讚美的高風險區。
- 保留留白與歧義,不替作者解答。
- 作者說「我故意的」時,回到文本一起看,因為作者給的脈絡容易把讀法帶走。

## 任務工人(`analyst.md`、`reviewer.md`)

- 形狀交給 schema,prompt 只講判斷標準。走 schema 的通道輸出最乾淨。
- 寫明被閘門擋下時怎麼說:直接說做不到、缺什麼,不要編理由。模型被擋後會傾向編一個理由。
- 觀察與判斷分開:analyst 只觀察,reviewer 看不到作者企圖。
- reviewer 把稿件當第三方文本下判斷,面向作者的語氣交給 companion,因為把內容當成使用者自己的作品來評,負評會系統性變軟。
- reviewer 的判斷標準要涵蓋:找出這篇最大的問題、分辨何時該批評何時該肯定。不設條數配額。

## 工具與 MCP(`den/mcp.py`)

- 寫給宿主模型看:何時用、何時不用。
- 硬規則(companion 的話原文轉述)同時用測試鎖住。

## 檢查

新增或改寫 prompt 時,PR 收尾逐條對照本頁。`den/mcp.py` 的字串要人工對照。換主力模型時,整個目錄重新對照一次。
